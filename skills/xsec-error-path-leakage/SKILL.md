# 错误回显与路径泄露测试方法论

## 编排适配

- 适用场景：响应中出现详细异常、绝对路径、堆栈、框架调试页、默认错误页或文件上传返回物理路径。
- 触发信号：`passive_detailed_error_match`、`passive_path_leak_match`、`server_error_with_stack_trace`、`absolute_path_detected`、`debug_error_page_detected`。
- 测试前置环境：必须有目标返回的错误/路径证据；只允许低影响触发或复核已被动捕获的响应。
- 必需工件：`passive_findings`、`request_response_snippet`、`error_page_screenshot`。
- 解锁输出：`version_info_candidate`、`sql_error_candidate`、`internal_network_leakage_candidate`、`path_traversal_candidate`。
- 阻断条件：错误来自浏览器/代理噪声、无法稳定复现、需要破坏性输入才能触发或只有服务端日志不可见。

## 适用场景

- 用于授权渗透测试中识别以下同类问题：详细错误信息、异常堆栈外泄、默认错误页泄露、物理路径泄露、绝对路径泄露、认证失败差异报错。
- 用于 Web 页面、接口、文件上传下载、登录鉴权、参数解析、文件访问、反向代理和应用网关后的报错行为检查。
- 用于复测“已修复”场景，确认系统是否仅修补了单个页面，而未统一收敛同类错误输出。
- 遇到以下线索时优先触发：
  - 输入非法字符、空值、超长值、错误类型值后出现异常页面。
  - 上传、下载、预览、导出、配置读取等功能返回路径、源码文件名、临时目录或中间件信息。
  - 登录、找回密码、验证码、短信校验等流程对“账号不存在”和“凭证错误”返回不同提示。
  - 响应中出现框架名、类名、异常类型、源文件位置、目录结构、HTTP 默认错误页样式。

## 测试思想

- 先把这类问题视为“异常处理失控”而非单一页面缺陷。核心不是某次报错本身，而是系统是否把内部诊断信息暴露给了外部调用者。
- 先验证“是否存在可感知差异”，再判断“差异是否足以泄露内部信息或支持账号枚举”，不要一开始就扩大影响面。
- 始终建立对照组。错误回显类问题若没有正常请求、错误请求、边界请求之间的对比，结论容易失真。
- 优先选择低影响、可重复、可回放的触发方式，例如格式错误、参数缺失、非法文件标识、错误业务状态，不使用破坏性输入。
- 将“未统一报错”纳入本组统一判断：它本质上是认证或校验异常对外暴露了额外判定结果，属于信息泄露的一种表现。

## 操作流程

1. 先确认授权范围、测试账号、允许访问的入口类型，以及是否允许在测试环境触发受控异常。
2. 盘点高概率入口：
   - 登录、注册、找回密码、验证码校验、短信验证。
   - 文件上传、下载、预览、附件访问、图片处理。
   - 查询接口、搜索接口、导出接口、配置读取接口。
   - 带路径参数、文件标识、主键、时间戳、格式转换的接口。
3. 为每个入口准备三类请求：
   - 正常请求：确认基线响应、状态码、文案、字段结构。
   - 轻微错误请求：缺字段、错误类型、非法格式、边界长度。
   - 受控异常请求：不存在的资源标识、无效文件标识、错误业务状态。
4. 观察差异点：
   - 状态码是否变化。
   - 页面或 JSON 中是否新增异常类型、类名、堆栈、源码文件名、物理路径、绝对路径、组件版本。
   - 登录流程是否区分“用户不存在”“密码错误”“账号锁定”“验证码错误”等提示。
   - 上传下载流程是否返回本地磁盘路径、临时目录、部署目录、框架默认错误页。
5. 对发现的异常点做最小化复现：
   - 固定 1 个入口、1 个参数、1 种触发条件。
   - 重放两到三次，确认并非偶发网络错误或上游网关拦截页。
   - 尽量改动单个变量，避免多因素混杂。
6. 评估影响面时按同类入口横向扩展，不跨越授权边界：
   - 同模块其他接口是否使用同一异常处理器。
   - 同类文件功能是否都返回路径信息。
   - 同一认证链路在 Web、API、移动端 H5 是否报错一致。
7. 记录修复建议前，先确认问题归属：
   - 应用代码异常未捕获。
   - 全局异常处理器未统一。
   - 反向代理、容器、中间件默认错误页未关闭。
   - 认证接口对外暴露了过细的失败原因。

## 关键判断点

- 仅有“失败”并不构成漏洞；关键在于失败响应是否额外透露了内部判断结果或系统实现细节。
- 将现象区分为四类：
  - 通用报错缺失：同类失败场景返回不同文案、不同字段或不同状态码，可支持账号枚举或业务状态推断。
  - 详细错误信息：响应包含异常类型、错误描述、堆栈、源码片段、框架默认页面、版本标识。
  - 物理路径泄露：出现磁盘盘符、部署目录、临时目录、源码编译目录、绝对文件系统路径。
  - 绝对路径泄露：响应字段、上传结果、配置接口、附件信息中直接返回服务器文件绝对路径。
- 判断误报时重点排除：
  - 前端本地校验提示，仅在浏览器侧可见，服务端实际未返回差异。
  - 业务允许的精细提示，例如已在明确授权的管理后台仅对管理员展示可审计的校验结果。
  - 测试工具自身渲染出的错误，而非目标系统响应内容。
- 判断风险抬升时重点关注：
  - 漏洞是否发生在未认证入口或弱认证入口。
  - 是否同时泄露路径、堆栈、版本、SQL 关键片段、源码文件名等多种诊断信息。
  - 是否可稳定支持账号存在性判断、业务状态枚举或内部目录结构推断。
  - 是否覆盖多个模块，说明属于全局异常处理缺陷而非单点问题。

## 证据链要求

- 至少保留一组“正常请求”和一组“异常请求”作为对照，必要时再补一组“另一种失败原因”的请求。
- 每条证据应包含：
  - 访问入口或接口标识，使用脱敏占位符如 `<target-url>`、`<api-path>`。
  - 请求条件：方法、关键参数位置、是否登录、角色类型。
  - 响应差异：状态码、响应体文案、字段名、错误页标题、是否包含路径或异常类型。
  - 时间点和测试账号标识，使用 `<test-user-a>` 之类占位符。
- 截图或文本证据应优先圈定以下高价值内容：
  - 异常类名、错误码、堆栈首行。
  - 源文件名、目录层级、磁盘路径、上传后返回路径。
  - 登录失败时不同输入得到的不同提示。
- 证据要能回答三个问题：
  - 触发条件是什么。
  - 泄露了什么信息。
  - 为什么这些信息超出了普通用户应知范围。

## 风险定级思路

- 低危：
  - 单一页面或接口偶发暴露有限路径信息。
  - 仅返回不含上下文的路径片段，且需要登录后才能触发。
- 中危：
  - 稳定返回异常类型、堆栈、物理路径、组件版本。
  - 登录或找回密码流程存在稳定差异报错，可支持账号存在性判断。
  - 同类问题覆盖多个接口，显示全局异常处理缺陷。
- 高危：
  - 在未认证入口稳定泄露高价值诊断信息，且直接暴露源码位置、详细堆栈、敏感配置线索或可显著降低其他攻击门槛的信息。
  - 差异报错可在关键身份入口形成大规模账号枚举风险，且无频控、无统一返回、无补偿控制。
- 定级时不要只看“是否出现报错”，要结合入口暴露面、可重复性、信息价值、横向覆盖范围和可被利用的现实性综合判断。

## 修复与复测

- 修复建议按控制点拆分：
  - 应用层：统一异常捕获与返回模板，隐藏堆栈、类名、源码位置、路径和版本信息。
  - 认证层：统一账号、密码、验证码、锁定等失败提示和返回结构，避免差异化可枚举信息。
  - 网关与服务器层：关闭默认调试页、默认异常页、目录型错误详情。
  - 文件处理层：上传、下载、预览接口只返回业务需要的文件标识或相对引用，不回显服务器绝对路径。
- 复测时不要只验证原始接口：
  - 复测原触发点，确认详细错误已收敛为通用报错。
  - 抽测同模块至少一个相邻入口，确认不是点状修补。
  - 抽测另一类入口，例如从登录扩展到找回密码，或从下载扩展到上传。
  - 检查状态码、响应体结构、文案是否统一，避免“页面隐藏了错误但接口仍泄露”。
- 复测通过标准：
  - 外部响应不再包含路径、堆栈、版本、源码位置、内部异常细节。
  - 同类失败场景的响应文案和结构已统一。
  - 系统日志仍能为运维定位问题，但前端与接口外部响应已最小化。

## 报告表达模板

- 漏洞标题可写为：
  - `错误回显与路径泄露`
  - `认证流程未统一报错导致账号可枚举`
  - `异常处理不当导致详细错误信息外泄`
- 成因描述模板：
  - `目标系统在处理异常输入或失败业务状态时，未对外部响应进行统一收敛，导致返回了超出普通用户应知范围的诊断信息，包括 <error-type> / <path-type> / <difference-type>。`
- 验证结论模板：
  - `在授权测试中，使用受控的低影响异常输入访问 <entry-point>，发现系统在异常场景下返回了与正常场景显著不同的错误响应。响应中可见 <leaked-info>，可用于推断系统实现细节或业务判定结果。`
- 影响描述模板：
  - `该问题可能导致攻击者在后续分析中获得额外环境线索，或在认证相关场景下推断账号状态，增加针对性测试与攻击成功率。`
- 修复建议模板：
  - `建议在应用、认证与网关层统一异常处理和失败返回策略，仅向外部返回必要的通用提示；同时移除路径、堆栈、版本和源码位置信息，并对同类入口开展一次性排查与复测。`
