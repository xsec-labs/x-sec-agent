# 云密钥与私钥泄露测试方法论

## 编排适配

先读 [运行边界与证据口径](../../references/security-boundaries.md)。在分配的节点、预算和低影响约束内执行；`scope_policy` 只做资产归因，新发现的目标记录来源即可，不因 `in_scope=false` 停止；证据保留观察到的原始值，报告与委派只取证明问题所需的最小片段。

- 适用场景：passive hook、前端源码、配置文件或接口响应中发现云厂商 AK/SK、STS、对象存储凭据、私钥、Webhook 或第三方 AppSecret。
- 触发信号：`passive_secret_match`、`passive_private_key_match`、`js_secret_candidate_detected`、`config_secret_candidate_detected`、`object_storage_credential_detected`。
- 测试前置环境：通常需要有疑似凭据及来源证据；优先使用只读身份/权限查询或客户提供的隔离测试资源。
- 参考工件：`passive_findings`、`source_location`、`raw_secret_value`、`vendor_hint`。
- 解锁输出：`cloud_credential_validated`、`object_storage_access_candidate`、`configuration_leak_chain_candidate`、`vulnerability_chain_input`。
- 建议阻断（可低影响补齐时先补证再测）：仅为脱敏/占位/公钥、无授权验证凭据、无法确认云厂商类型或验证会触碰真实敏感资源。

## 适用场景

- 适用于渗透测试中发现云厂商访问密钥、临时安全令牌、对象存储上传凭据、云主机管理凭据、SSH 私钥、RSA 私钥或其他可用于云资源访问的高价值凭据。
- 同样适用于发现微信公众号/小程序 AppID+AppSecret、微信支付 MchID+APIKey、钉钉 AppKey+AppSecret/机器人 Webhook、飞书 AppID+AppSecret/Webhook 等第三方平台密钥泄露。
- 常见入口包括前端 JavaScript、小程序或移动端包体、源码映射文件、公开配置接口、上传初始化接口、调试接口、错误回显、静态配置文件、构建产物和日志回显。
- 统一处理近义标题：`AK/SK 密钥泄露`、`云主机密钥泄露`、`私钥泄露`、`AppSecret 泄露`、`Webhook 泄露` 都属于"凭据被低权限用户或未授权访问者获取"的问题，差异主要在凭据类型、权限范围和验证方式。
- 不得使用泄露凭据接管真实主机、下载真实敏感文件、修改或删除云资源。

## 测试思想

- 先判断“是否真凭据”，再判断“谁能拿到”，最后判断“拿到后能做什么”。密钥字符串本身不是完整结论，风险结论依赖暴露面、有效性、权限范围、生命周期和可续期性。
- 把凭据按类型拆分：
  - 长期云 AK/SK：关注是否仍有效、是否绑定高权限策略、是否可访问多个区域或多个云产品。
  - STS 或临时 Token：关注是否由公开接口持续签发、有效期是否过长、策略是否过宽、是否可反复获取。
  - 对象存储上传/下载凭据：关注是否限制 bucket、路径前缀、操作类型、文件类型、过期时间和来源身份。
  - 私钥：关注其是否真为私钥而非公钥、是否可用于解密/签名/登录、是否和前端业务流程直接绑定。
- 优先采用低影响验证：只证明凭据可被非预期主体获取，并在客户确认的测试资源、空目录、测试对象或权限模拟结果上验证能力，避免触碰真实业务数据。
- 区分误报与真实风险：
  - 前端公开公钥通常不是私钥泄露，但如果同一处同时暴露解密私钥、签名私钥或云凭据，则按高风险处理。
  - 已脱敏、占位、无效或过期凭据不直接等同于有效泄露，但如果公开接口可持续返回新凭据，仍应按真实风险验证。
  - 仅能上传到严格隔离的临时目录且不可读、不可覆盖、短期失效时，风险可能低于全量 AK/SK，但仍需评估滥用、覆盖、存储成本和数据污染风险。

## 参考方法（目标与常见路径，不是必须顺序）

下面是达成测试目标的常见路径，不是必须照做的脚本：可以合并步骤、调整顺序、跳过已经确认过的部分，或者换成你判断更合适的方法，只要仍能支撑下面的判断点和证据要求。

1. 信息收集
   - 明确测试账号角色、允许验证的云账号或测试资源、禁止触碰的数据类型和留证边界。
   - 梳理应用形态：Web、App、小程序、管理后台、文件上传链路、在线办理链路、云存储直传链路、前端加解密链路。
   - 从前端包、静态资源、接口响应、配置文件和错误信息中记录疑似字段名，例如 `<access-key-id-field>`、`<secret-key-field>`、`<token-field>`、`<private-key-field>`。
   - 原始敏感内容保存到受控证据目录；共享发现、截图展示、报告和委派使用最少必要的原始摘录（xSec 不做自动脱敏）与证据引用，截断只因体积限制并明确标记。

2. 构造对照组
   - 使用未登录、低权限账号、正常业务账号和高权限账号分别访问同一入口，比较凭据字段是否出现、内容是否不同、权限策略是否随角色变化。
   - 比较不同业务流程：上传初始化、文件预览、资料申请、登录前配置加载、页面刷新和接口重放后的返回差异。
   - 比较不同时间点：观察临时凭据是否会更新、过期后是否仍可重新获取、密钥有效期是否明显超出业务需要。

3. 最小化验证
   - 对疑似云 AK/SK 或 STS 凭据，只验证身份可识别、权限策略可解析、授权资源范围可确认；需要实际访问时，仅访问客户指定的空白测试资源或只读元数据。
   - 对对象存储凭据，优先验证策略是否限定到测试 bucket、测试前缀、单一动作和短过期时间；不得下载、预览、转存真实业务文件。
   - 对私钥，先识别其格式和用途，再使用本地自造样本或客户提供的测试样本验证加解密/签名能力；不得解密真实业务密文或伪造真实业务请求。
   - 记录最小证明链：低权限主体能够获取凭据，凭据未被充分掩码，凭据对应云资源或密码学能力，权限边界超过前端或当前角色的必要范围。
   - 使用官方 CLI/SDK 工具执行只读身份验证命令；具体命令见"官方工具验证命令"章节。

4. 影响面扩展
   - 在不触碰真实数据的前提下评估影响：可访问的云产品类型、资源命名范围、区域范围、bucket/前缀范围、动作范围、有效期、是否可续期。
   - 关注组合链路：前端暴露接口可取临时 Token，Token 又具备对象存储读写能力；前端私钥可解密敏感参数；长期 AK/SK 可进一步管理云资源。
   - 扩展只做“范围确认”，不做破坏性动作、不做批量枚举、不做数据下载。需要进一步确认时，要求客户提供隔离测试资源或由客户侧执行验证。

5. 留证
   - 保存凭据来源入口的完整原始请求/响应或源码位置截图，敏感值保留完整原文。
   - 保存对照组差异：不同角色、登录态、时间点下字段是否返回，以及权限范围是否变化。
   - 保存验证证据：原始测试资源名称、权限策略、只读元数据结果、过期时间、验证时间点和操作者账号角色。
   - 验证过程保持只读和最小化，不下载真实文件、不登录真实主机、不修改云资源。

6. 修复复测
   - 复测同一入口和同类入口，确认敏感字段不再出现在前端包、公开接口、配置响应和错误回显中。
   - 确认泄露密钥已经吊销或轮换，而不是只删除页面展示；旧凭据应无法再通过任何授权路径使用。
   - 确认临时凭据由后端按需签发，策略最小化到必要资源、动作和时间窗口，并与调用者身份绑定。
   - 对私钥泄露，确认私钥只在服务端或受控密钥管理服务中使用，前端仅保留公钥或非敏感配置。

## 关键判断点

- 暴露主体：未登录用户、任意低权限用户、普通业务用户、特定角色用户，分别对应不同风险级别和整改优先级。
- 凭据真实性：字段名、格式、长度、前缀、有效期、云厂商返回结构、错误码和权限策略共同判断，避免只凭关键字定性。
- 权限范围：能否访问多个 bucket、多个路径、多个云产品或云主机资源；是否具备读、写、删除、策略修改、实例管理等高危动作。
- 生命周期：长期 AK/SK 风险通常高于短期受限 Token；但公开接口可持续签发 Token 时，应按持续泄露评估。
- 业务必要性：前端直传可以使用受限临时凭据，但不应暴露长期密钥、宽权限 Token 或服务端私钥。
- 私钥判定：明确区分公钥、私钥、对称密钥、签名密钥和证书片段。只有具备保密属性且可执行敏感能力的材料才按私钥泄露处理。
- 复测充分性：只删除单个入口不代表修复完成，应覆盖同类接口、历史构建产物、缓存、CDN、移动端旧版本和配置中心。

## 证据链要求

- 来源证据：凭据出现的页面、接口、前端文件或配置位置；保留原始访问身份、时间点、入口路径和原始截图。
- 可获取性证据：未登录或低权限主体能够拿到敏感字段；对照组显示该返回不应对当前主体开放。
- 凭据属性证据：凭据类型、完整原始值、是否临时、过期时间、绑定策略、资源范围和动作范围。报告和共享发现中必须保留完整值供后续复用。
- 最小验证证据：只读元数据、权限模拟、测试资源访问结果或客户侧验证回执，证明风险存在而未触碰真实敏感数据。
- 影响证据：可能导致的数据泄露、资源滥用、存储污染、服务中断、云资源被管理或加密体系失效，应和权限范围一一对应。
- 边界证据：说明测试未进行批量真实数据下载、未执行删除/修改、未登录真实主机、未执行跨账号角色切换等横向移动；目标是否在初始 scope 内不作为访问限制。

## 风险定级思路

- 高危：
  - 长期 AK/SK、云主机管理凭据或服务端私钥被未授权或低权限主体获取。
  - 临时凭据可通过公开入口持续签发，且权限覆盖敏感资源读写、云资源管理或跨业务范围访问。
  - 对象存储凭据允许读取真实敏感文件、覆盖业务文件、删除对象或访问范围明显超过当前业务目录。
- 中危：
  - 临时凭据有效期较短但策略过宽，或仅能访问有限资源但仍可造成数据污染、费用损失或越权读取测试范围内数据。
  - 私钥用途受限但仍可影响部分业务加解密、签名校验或客户端安全边界。
- 低危或信息泄露：
  - 仅暴露公钥、无效样例、已过期且无法续期的历史凭据，或仅返回严格受限、短期、单动作、单路径的临时凭据，但仍存在配置暴露和审计改进空间。
- 定级时同时考虑获取门槛、权限范围、有效期、是否可续期、是否接触敏感数据、是否可造成云资源变更和修复复杂度。

## 修复与复测

- 立即处置：
  - 吊销或轮换已泄露的 AK/SK、STS 签发源密钥、对象存储密钥、SSH 私钥和业务加密私钥。
  - 排查访问日志和云审计日志，确认泄露窗口内是否存在异常调用、异常下载、异常上传、策略变更或实例操作。
  - 清理前端构建产物、CDN 缓存、移动端旧包、配置接口和日志中的残留敏感值。
- 架构修复：
  - 长期密钥只保存在服务端密钥管理系统、环境变量托管服务或云厂商 KMS/Secrets Manager 中。
  - 前端上传使用后端签发的短期、单用途、最小权限凭据，并绑定用户、业务对象、路径前缀、文件大小、文件类型和过期时间。
  - 私钥不得下发到前端；需要客户端加密时前端只持有公钥，解密和签名能力保留在服务端或受控硬件/密钥服务中。
  - 云账号权限按最小权限拆分，禁止一个密钥同时具备对象存储、主机管理、策略管理等宽权限。
- 复测方法：
  - 使用原发现入口复测字段是否消失或被替换为无敏感含义的临时票据。
  - 使用未登录、低权限、正常账号和过期会话进行对照，确认敏感字段不会被越权返回。
  - 验证旧密钥不可用，新凭据策略收敛到必要资源和动作，临时凭据过期后不能被离线复用。
  - 检查同类入口、历史版本、静态资源缓存和移动端包，避免只修一个接口导致漏判。

### 影响范围
- 暴露入口：`<endpoint-or-bundle-file>`
- 可获取主体：`<unauthenticated-or-low-privileged-role>`
- 凭据类型：`<ak-sk-or-sts-or-private-key>`

### 验证过程
1. 使用 `<actor-role>` 访问 `<entry-point>`，响应或前端文件中出现 `<raw-credential-fields>`，报告中填入捕获到的原始字段和值。
2. 使用 `<control-role>` 进行对照，确认敏感字段返回逻辑与身份权限不匹配。
3. 在指定的 `<test-resource>` 上进行最小化验证，确认凭据可用于 `<safe-verification-result>`。
4. 测试过程中未下载真实业务数据、未修改或删除云资源、未登录真实主机。

### 风险说明
凭据泄露可能造成云资源越权访问、敏感文件读取、对象覆盖、资源滥用、费用损失或业务加密体系失效。实际风险取决于凭据权限、有效期、是否可持续获取和资源范围。

### 修复建议
1. 立即吊销并轮换已泄露凭据，排查云审计日志中的异常访问。
2. 移除前端包、公开接口、配置响应和缓存中的敏感字段。
3. 改为服务端按需签发短期、最小权限、绑定用户与业务对象的临时凭据。
4. 私钥仅保存在服务端或密钥管理服务中，前端不得持有解密或签名私钥。
5. 对同类接口、历史版本和静态资源缓存进行全量复查。
