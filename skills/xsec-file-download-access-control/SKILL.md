# 文件下载访问控制缺陷测试方法论

## 编排适配

- 适用场景：发现附件下载、文件预览、导出、图片/文档读取、临时链接、签名 URL 或文件中心接口，需要验证下载对象权限。
- 触发信号：`file_download_endpoint_detected`、`file_preview_endpoint_detected`、`attachment_id_detected`、`signed_download_url_detected`、`export_endpoint_detected`、`id_like_resource_paths_detected`。
- 测试前置环境：必须有授权测试账号和至少一个归属当前账号的文件/链接；水平验证最好有第二账号或客户提供的测试文件。
- 必需工件：`request_corpus`、`api_inventory`、`browser_state`、`owned_file_baseline`、`second_account_file_baseline`。
- 解锁输出：`file_download_access_control_candidate`、`path_traversal_candidate`、`sensitive_data_exposure_candidate`、`idor_candidate_detected`。
- 阻断条件：无下载/预览入口、无测试文件、下载会获取真实敏感数据或接口为写操作/一次性不可复现链接。

## 适用场景

- 适用于 Web 系统、移动端接口、H5 页面、后台管理端中与文件下载、附件预览、导出留痕相关的功能。
- 适用于下载入口表现为按钮、附件列表、导出中心、审批记录、资料中心、文档详情、打印或预览跳转的场景。
- 适用于下载请求中存在文件 `id`、附件编号、资源编码、业务单号、文件名、状态位、分享标识、短期 token 等对象定位参数的场景。
- 适用于怀疑文件本应按用户、角色、租户、项目、流程状态或发布状态隔离，但服务端未做对象级校验的场景。
- 不适用于纯粹的本地文件包含、目录穿越或任意路径读取问题；若核心成因是文件系统路径拼接，应转入相应方法论。

## 测试思想

- 这类问题的核心不是“接口能下载文件”，而是“服务端是否确认当前主体对目标文件具备合法下载权”。
- 优先把问题拆成两类：
  - 任意文件下载：用户无需具备对应业务关系，靠可控对象标识或状态差异即可获取本不应公开的文件。
  - 越权文件下载：已登录低权限主体通过替换对象标识、切换文件编号或复用链接，下载其他用户、其他流程、其他项目的文件。
- 判断时不要被“参数被编码”“文件名随机”“带 token”误导。若服务端仍以客户端可控值直接定位文件，而未绑定当前身份或业务上下文，风险依旧成立。
- 必须使用对照组思维。单次下载成功不足以证明漏洞，需回答三个问题：
  - 当前文件原本是否只应对特定主体开放。
  - 变更了哪些最小参数后仍能成功返回目标文件。
  - 服务端返回的是授权结果，还是仅凭对象存在与否直接下载。
- 所有验证限定在授权、低影响、最小化语境。证明“可越权下载一个最小样本”通常已经足够，不需要扩展枚举。

## 操作流程

1. 信息收集
- 识别所有文件相关入口：附件列表、下载中心、审批流附件、详情页导出、打印页、历史记录、分享页、预览转下载接口。
- 抓取一次正常下载，记录请求方法、路径、关键参数、响应头、文件类型、文件名生成方式、是否依赖登录态。
- 观察前端是否暴露对象标识，如连续数字、短编码、业务单号、Base64、简单映射或可从页面源码直接取出的附件编号。

2. 建立基线
- 使用当前账号先下载自己有权访问的文件，确认正常授权链路和返回特征。
- 记录基线请求中的文件标识、业务对象标识、用户态、响应状态码、`Content-Type`、`Content-Disposition`、响应长度等特征。
- 判断该文件是公开资料、登录后共享资料，还是严格私有资料；避免把本就公开的下载误判为漏洞。

3. 构造对照组
- 对照组一：同账号、同流程内其他自己有权文件，用于识别编号规则与正常返回差异。
- 对照组二：同账号下理论无权的对象，例如其他记录、其他状态、其他项目、未发布资料或不同租户文件。
- 对照组三：如具备多角色测试条件，准备高权限与低权限、拥有者与非拥有者两个主体，比较同一文件请求结果。
- 若接口带 `token`、签名或编码参数，优先验证其是否只是定位辅助值，避免把“看起来复杂”当成真实控制。

4. 最小化验证
- 在基线请求上只替换一个关键对象参数，例如文件 `id`、附件编码、关联单号或路径段中的资源编号。
- 优先选取已知存在但当前主体理论无权访问的最小样本，不进行批量枚举、不进行高频探测。
- 如果参数经过简单编码或映射，仅在授权测试范围内验证“替换后仍可定位其他文件”这一事实，不沉淀可用于真实攻击的还原细节。
- 关注成功特征：返回 200、附件头、内容长度明显变化、文件预览成功、响应体为真实二进制而非错误页。

5. 判断授权缺失位置
- 判断是否缺少登录态校验：未登录或失效会话是否仍可下载。
- 判断是否缺少对象级校验：已登录但无权主体替换对象标识后是否仍能下载。
- 判断是否缺少状态校验：未发布、已删除、历史版本、审批中资料是否可被直接下载。
- 判断是否缺少租户或项目边界校验：同角色但不同组织、不同项目间是否可交叉获取文件。

6. 影响面扩展
- 仅在低频前提下确认同类接口是否复用相同授权缺陷，例如预览、导出、缩略图、打包下载、移动端下载链路。
- 比较不同文件类型是否一致受影响，如图片、PDF、表格、压缩包、审批附件。
- 评估影响对象类别：个人资料、合同协议、证书证明、内部文档、业务台账、研究资料、财务附件等。

7. 留证
- 保留一次正常下载和一次最小化越权下载的完整请求响应对照。
- 截图或导出时对文件内容、姓名、编号、路径、令牌等敏感信息做脱敏，只保留足以证明“非本人/非本项目/未发布”的必要片段。
- 固定测试时间、账号角色、业务记录关系、参数变更点和返回差异，确保报告能说明因果链。

8. 修复复测
- 修复后使用原始基线请求与原始越权变体分别复测，确认无权请求被拒绝且返回一致的错误语义。
- 复测同族接口与不同入口，避免只修一个下载接口而遗漏预览、导出、移动端或历史版本接口。
- 复测不同角色、不同状态、不同组织边界，确认控制点已下沉到服务端对象授权而非前端页面隐藏。

## 关键判断点

- 下载接口是否仅依赖客户端传入的文件标识定位资源，而未校验该文件与当前用户、当前业务对象的关系。
- 所谓 `token`、签名、编码值是否真正参与授权判断，还是只是对象定位、时间戳拼接或可复用链接参数。
- 成功响应是否体现出“对象存在即返回”，而不是“有权才返回”；常见信号包括替换编号后直接得到不同文件、不同长度或不同类型的附件。
- 文件是否属于敏感范围。公开宣传资料与严格私有附件的风险边界不同，定性时必须说明预期访问范围。
- 是否存在横向越权和纵向越权两类问题：
  - 横向越权：同权限不同用户、不同记录之间可互下文件。
  - 纵向越权：低权限主体可下载本应仅高权限、审核人或管理员可见的资料。
- 是否存在状态绕过：未发布、已归档、已撤回、历史版本、草稿附件仍可通过直接接口下载。
- 不要把“文件编号连续”本身当成漏洞。真正的问题是编号可控且服务端未结合身份、角色、状态、租户做判定。

## 证据链要求

- 证据至少覆盖六个要素：入口位置、正常授权样本、越权变更点、返回成功特征、目标文件归属差异、测试主体关系。
- 建议保留以下材料：
  - 正常下载请求与响应摘要，证明当前账号对基线文件有权。
  - 越权请求与响应摘要，证明仅替换最小对象参数后获得了无权文件。
  - 文件归属或发布范围的界面证据，证明目标文件不应对当前主体开放。
  - 脱敏后的响应头或文件内容片段，证明返回的是实际文件而非占位页。
  - 测试账号角色说明，例如“文件拥有者/非拥有者”“高权限/低权限”“同租户/跨租户”。
- 若无法安全展示文件正文，可使用脱敏后的文件名、类型、页眉、摘要片段或业务标识证明对象已变化。
- 若存在状态型问题，应补充“未发布/草稿/历史版本”证据，证明问题不只是普通共享下载。

## 风险定级思路

- 高危：
  - 可下载高敏感业务文件，且影响范围跨用户、跨项目、跨租户或可访问审批、合同、证件、研究、财务等资料。
  - 缺陷稳定存在于核心下载链路，低权限主体可直接复现，服务端无有效对象校验。
- 中危：
  - 可下载非公开但敏感度相对有限的内部文件，或影响面局限于单模块、单角色边界内。
  - 需要已登录前提，但成功后仍能证明对象授权缺失。
- 低危：
  - 仅能访问误配置的低敏感公开资源、旧测试文件或影响范围极窄的边缘资料，且难以形成进一步风险。
- 升级因素：
  - 文件内容涉及个人隐私、证照、合同、财务、研究资料或其他高价值信息。
  - 可通过简单相邻编号或固定模式稳定命中其他文件。
  - 多个接口共用同一缺陷，或未登录也可访问。
- 降级因素：
  - 目标文件本就设计为公开下载。
  - 仅能获取当前主体已授权范围内的等价文件，无法证明越权或未发布访问。

## 修复与复测

- 修复方向
  - 在服务端对每次下载请求执行对象级授权校验，绑定当前用户、角色、租户、项目、流程状态与文件归属关系。
  - 不信任客户端传入的文件标识、文件名、分享参数、Cookie 中的身份字段或前端拼出的业务对象编号。
  - 对未发布、草稿、归档、历史版本等状态增加显式状态校验，不允许通过直接接口绕过页面流程。
  - 对分享下载或临时链接设置最小权限、短时效、一次性或与主体绑定的控制，而不是把链接本身当授权。
- 复测重点
  - 使用原成功样本确认合法下载不受影响。
  - 使用原越权样本确认被拒绝，且返回统一、不可枚举的错误语义。
  - 复测预览、导出、缩略图、压缩包下载、移动端接口、历史附件接口是否同步修复。
  - 复测跨角色、跨记录、跨组织、跨状态场景，避免局部补丁导致旁路仍存在。

## 报告表达模板

- 漏洞标题
  - 文件下载访问控制缺陷
- 漏洞描述
  - 在授权测试过程中，发现系统下载接口在处理文件资源时，对当前主体与目标文件之间的授权关系校验不足。测试人员在合法登录并获取一个正常下载请求后，仅替换 `<file-id>` 或等价对象定位参数，即可访问本不应向当前主体开放的文件资源。
- 影响说明
  - 该问题可能导致攻击者在授权边界外获取 `<file-category>` 类型文件，造成敏感资料泄露、业务信息外流或跨用户数据暴露。若受影响对象覆盖多角色、多项目或多租户边界，风险将进一步扩大。
- 证据概述
  - 1. 使用 `<authorized-role>` 对自身有权文件发起正常下载，请求成功。
  - 2. 保持其余参数不变，仅将对象定位参数替换为 `<unauthorized-object>` 对应值后，接口仍返回真实文件。
  - 3. 结合页面归属信息或业务关系可证明该文件不属于当前主体的授权范围。
  - 4. 响应头、文件类型、脱敏内容片段表明返回结果为实际文件而非错误页。
- 修复建议
  - 建议在服务端统一落实文件对象级授权校验，将文件访问与当前身份、角色、租户、业务对象和状态绑定校验；同时排查所有预览、导出、分享、历史版本等同族接口，确保不存在旁路下载。
