# 不安全密码策略测试方法论

## 编排适配

- 适用场景：发现注册、改密、重置、首次登录改密、管理员创建用户或弱口令可设置流程，需要验证密码复杂度、历史、有效期和默认密码策略。
- 触发信号：`password_change_flow_detected`、`password_reset_flow_detected`、`registration_form_detected`、`admin_user_create_detected`、`first_login_password_change_detected`、`weak_password_set_attempt_allowed`。
- 测试前置环境：必须有可控测试账号；改密/重置动作需要授权方允许并确认可恢复，不影响真实用户。
- 必需工件：`forms/actions`、`request_corpus`、`browser_state`、`test_account_credentials`、`password_policy_observations`。
- 解锁输出：`weak_password_settable`、`session_token_invalidation_candidate`、`brute_force_protection_review_needed`。
- 阻断条件：无密码管理流程、无测试账号、无法恢复密码或授权禁止修改账号状态。

## 适用场景

- 目标系统存在注册、首次登录、修改密码、忘记密码、管理员重置密码、批量初始化账号等功能。
- 已观察到密码策略提示文案，但需要确认后端是否真实执行，而非仅前端校验。
- 已拿到授权测试账号，需要在低影响前提下验证弱复杂度密码、历史密码重用、默认密码、长期不过期或重置后不强制改密等问题。
- 需要判断“策略未配置”“策略配置但未生效”“仅部分入口生效”“仅 UI 提示存在”这几类差异。
- 需要给出可复测、可报告、可推动整改的密码安全方法论，而不是单点截图结论。

## 测试思想

- 先识别密码策略控制点，再验证控制点是否在所有入口一致生效。密码策略问题常见于“界面有规则，服务端不拦截”或“主流程拦截，旁路入口未拦截”。
- 优先做最小化验证，不追求批量尝试。核心是证明策略缺失或失效，而不是证明可以大规模猜解。
- 一定设置对照组。至少准备一组预期应被拒绝的低复杂度样本和一组预期应被接受的合规样本，用来区分真实缺陷、提示文案错误和测试操作偏差。
- 将密码策略拆成多个控制面分别判断：复杂度、长度、与用户名相似度、历史密码重用、有效期、首次登录强制改密、重置后临时密码生命周期、失败次数限制。
- 风险判断不只看“能否设置弱口令”，还要看影响账号范围、入口可达性、是否需要已知旧密码、是否能由低权限用户稳定触发、是否与默认密码或重置流程组合。

## 操作流程

1. 信息收集
- 盘点所有与密码有关的入口：个人资料改密、首次登录改密、忘记密码、管理员重置、用户导入初始化、移动端改密、开放 API。
- 记录页面规则提示、帮助文案、密码输入框约束、错误提示、是否存在“密码有效期”“不得与用户名相同”“首次登录必须修改”等策略配置项。
- 明确测试前提：测试账号角色、是否知道旧密码、是否允许创建临时账号、是否允许管理员协助重置。

2. 建立对照组
- 准备最少两组样本：`<低复杂度样本>` 与 `<合规样本>`，仅用于验证是否被拒绝或接受。
- 如需测试历史密码重用，再准备 `<历史密码样本>`；如需测试重置流程，再准备 `<重置后临时密码样本>`。
- 所有样本仅用于当前授权账号，避免影响真实用户账号和批量数据。

3. 入口级验证
- 在前端直接操作每个密码相关入口，观察低复杂度样本是否被拒绝、拒绝位置在前端还是后端、返回信息是否明确。
- 若前端拦截，再在授权语境下检查请求提交后服务端是否仍会接受被修改的密码字段，重点关注改密接口和重置接口是否存在校验缺失。
- 对配置类场景，核对策略项是否只是展示值存在，还是实际限制已经施加到账号生命周期。

4. 差异化验证
- 逐项验证复杂度规则是否真正生效：长度、字符类型、与账号标识相似、连续字符、纯数字、纯字母、常见弱模式。
- 验证历史密码限制是否生效：修改后再尝试回退至近期密码，确认是否被拒绝。
- 验证有效期与首次改密：初始化或重置后的口令是否要求首次登录修改，长期未改密是否会被提示或阻断。
- 验证重置链路：管理员重置、忘记密码、自助重置是否共享同一套后端策略。

5. 最小化影响确认
- 一旦证明某入口存在缺陷，立即停止额外尝试，改用截图、响应差异和结果状态固化证据。
- 如需确认漏洞闭环，仅验证一次“设置成功”与一次“使用新密码重新认证成功”即可，不做重复操作。
- 若系统存在锁定、审计或通知机制，提前与授权方确认窗口，避免触发运营告警。

6. 影响面扩展
- 不做横向尝试，只评估同类入口是否共用组件、共用接口或共用身份体系。
- 从“单入口缺陷”扩展到“同认证域缺陷”时，依据是代码路径、接口复用、统一身份平台或统一策略配置，而不是猜测。
- 若发现默认密码、弱复杂度可设置、密码不过期、重置后不强制改密同时存在，应按组合链路评估整体风险。

## 关键判断点

- 页面写着有规则，不代表服务端校验存在；服务端返回成功才是关键判断依据。
- 单一弱样本通过，不等于完整策略缺失；要判断是长度、字符种类、相似度、历史密码还是有效期中的哪一项失效。
- 配置项存在且值可见，不等于策略已启用；要看实际账号是否被约束。
- 改密成功但无法重新登录，可能是前端展示成功、后端未真正落库，也可能是异步生效；必须用一次受控重新认证确认结果。
- 仅管理员重置链路失效时，风险通常高于普通用户自助改密失效，因为影响账号范围更广。
- 若只有前端提示缺失、但后端严格拒绝，则更接近可用性或一致性问题，不应直接上升为高风险密码策略漏洞。
- 历史密码重用、密码不过期、默认密码长期有效，即使复杂度满足，也仍属于密码策略缺陷，应独立记录控制点失效。

## 证据链要求

- 保留入口定位证据：功能页面、策略提示、配置页或帮助说明的脱敏截图。
- 保留请求与响应证据：仅保留必要字段名、状态码、错误码、返回文案，不记录真实账号、真实密码、Token、Cookie。
- 保留对照证据：同一入口下，`<低复杂度样本>` 与 `<合规样本>` 的处理差异，或前端拦截与后端接受之间的差异。
- 保留结果证据：修改成功提示、一次受控重新认证成功、或策略未触发的配置项状态。
- 保留时间线：测试时间、账号角色、入口名称、前置条件、触发步骤编号，确保复测人员可在授权环境中复现。
- 若涉及默认密码或重置策略，只证明“存在可预测或未强制修改的状态”，不要在证据中暴露真实初始口令内容。

## 风险定级思路

- 高风险
- 可由普通用户或管理员在核心入口稳定设置低复杂度密码，且可立即用于登录。
- 弱复杂度缺陷与默认密码、重置后不强制改密、密码长期不过期等组合出现，影响同认证域多个账号。
- 管理端批量初始化或重置流程缺少策略校验，影响面可能超出单账号。

- 中风险
- 仅部分入口存在后端校验缺失，但需要已登录、自有账号且影响范围主要限于当前账号。
- 复杂度规则基本存在，但历史密码重用、有效期、首次改密等控制点缺失，短期内增加账户被复用和长期暴露风险。

- 低风险
- 主要表现为前端提示与后端策略不一致，或配置项设计薄弱但当前核心认证链路仍有补偿控制。
- 仅在低频管理场景可观察到策略缺口，且需要较强前置条件、影响账号有限。

- 降级因素
- 已启用多因素认证、异常登录拦截、失败锁定、首次登录强制改密等补偿措施且覆盖完整。
- 缺陷仅存在于不可达、已下线或仅测试环境入口，但这一点必须有证据支持。

## 修复与复测

- 修复方向应先统一后端策略引擎，再让前端文案与之保持一致，避免“多入口多规则”继续分叉。
- 最低整改面通常包括：最小长度、字符复杂度、与用户名相似度限制、历史密码重用限制、有效期策略、重置后临时密码强制修改、失败次数限制。
- 对默认密码或初始化密码场景，应改为一次性口令或首登强制改密，避免长期静态初始值。
- 对忘记密码和管理员重置链路，应复用同一后端校验与审计逻辑，不允许旁路入口放宽规则。
- 复测时不要只测原始入口，至少覆盖改密、自助重置、管理员重置三个方向中实际存在的全部入口。
- 复测要保留一组反例和一组正例：确认低复杂度样本被拒绝、合规样本被接受、历史密码不可重用、重置后首次登录需要改密。
- 若整改声明包含补偿控制，如 MFA 或锁定策略，复测中应确认其确实启用且与密码策略联动，而不是仅在文档中存在。

## 报告表达模板

- 标题
- 不安全密码策略

- 问题概述
- 在授权测试中发现，目标系统的密码策略控制存在缺失或未一致生效，导致账号可在 `<入口名称>` 中设置不符合安全要求的密码，或在 `<策略控制点>` 上未受到有效约束。

- 影响说明
- 该问题会降低账户口令强度与生命周期安全性，增加账号被猜测、重用或长期暴露的风险。若与默认密码、重置流程或统一认证入口组合，影响面可从单账号扩大至同认证域多账号。

- 复现概述
- 使用授权测试账号，在 `<入口名称>` 中分别提交 `<低复杂度样本>` 与 `<合规样本>` 作为对照；结果显示系统对前者 `<未拒绝/仅前端拒绝但后端接受/未要求首次改密/允许历史密码重用>`，表明 `<策略控制点>` 未有效生效。

- 证据摘要
- 证据包含：入口页面策略提示、脱敏请求与响应、修改结果提示、一次受控重新认证结果，以及同入口对照样本的差异记录。

- 修复建议
- 建议在统一后端策略层实施密码复杂度、历史密码、有效期、重置后强制改密和失败次数限制，并确保所有密码相关入口复用同一套校验与审计逻辑；整改后对全部相关入口执行一致性复测。
