# 路径遍历与文件遍历测试方法论

## 编排适配

先读 [运行边界与证据口径](../../references/security-boundaries.md)。在分配的节点、预算和低影响约束内执行；`scope_policy` 只做资产归因，新发现的目标记录来源即可，不因 `in_scope=false` 停止；证据保留观察到的原始值，报告与委派只取证明问题所需的最小片段。

- 适用场景：发现文件下载/预览、路径参数、文件名参数、静态资源目录、导入导出、URL 代取或附件 ID，需验证目录遍历/路径穿越。
- 触发信号：`path_parameter_detected`、`filename_parameter_detected`、`file_download_endpoint_detected`、`file_preview_endpoint_detected`、`static_file_route_detected`、`traversal_error_hint_detected`。
- 测试前置环境：通常需要有文件/路径处理接口和安全的测试载荷；优先对当前账号自有文件或公开测试文件验证。
- 参考工件：`request_corpus`、`api_inventory`、`owned_file_baseline`、`error_response_snippet`。
- 解锁输出：`path_traversal_candidate`、`file_download_access_control_candidate`、`config_backup_candidate_detected`、`error_path_leakage_candidate`。
- 建议阻断（可低影响补齐时先补证再测）：无路径/文件参数、接口只接受不可控 ID、验证会读取真实敏感文件。

适用于低影响验证。目标是用最少请求证明访问控制或目录暴露失效，而不是扩大战果或批量获取数据。

## 适用场景

- 目标站点或接口存在可直接访问的目录路径，访问后出现目录索引、父目录入口、文件清单或默认目录页。
- 业务存在下载、预览、导出、附件、报表、模板、图片、文档等文件访问接口，参数可能是 `fileId`、`docId`、`path`、`name`、`key`、`code` 或路径片段。
- 测试中已具备测试身份，但怀疑低权限账号、跨角色账号或跨租户账号可访问不属于自己的文件对象。
- 前端、抓包记录、错误页或响应头暴露了文件名、目录名、存储路径、默认静态目录或可预测对象标识。
- 目录浏览与文件对象遍历常同时出现：前者暴露目录结构和敏感文件名，后者允许通过可预测标识读取文件内容。
- 若某路径本就设计为公开静态资源区，不直接判为漏洞；先确认是否超出公开范围、是否暴露配置/备份/日志/业务附件等非公开对象。

## 测试思想

- 先判断问题属于哪一类：目录索引暴露、文件读取越界，或两者并存。分类清楚，后续取证和定级才不会混乱。
- 先做对照，再做结论。任何“能访问”都应与“本应不能访问”的请求做差异比较，而不是只凭单次 200 响应下结论。
- 优先最小化验证。能用目录名、文件名、响应头、文件大小、内容类型证明问题时，不必下载完整文件。
- 优先证明控制点失效，而不是证明数据有多敏感。风险核心是“访问边界被突破”，不是“拿到了多少条数据”。
- 对目录遍历，核心在于服务器配置或发布目录暴露；对文件遍历，核心在于路径约束、对象映射或对象级授权缺失。
- 对同一问题要同时看“入口”与“边界”：谁能访问、能访问到哪里、是否可稳定复现、是否能跨账号或跨业务对象。

## 操作流程

1. 信息收集
- 识别可能的入口：站点根路径、静态资源目录、上传目录、备份目录、下载接口、预览接口、导出接口、附件接口、模板接口。
- 记录认证上下文：未登录、低权限、普通业务账号、不同角色账号、不同租户账号。后续所有判断都依赖这个上下文。
- 建立基线请求：一个确认可访问的正常对象、一个无效对象、一个理论上不应暴露的目录或对象。

2. 构造对照组
- 对目录浏览场景，对照“存在的目录”“不存在的目录”“同级目录”“修复后目录”四类响应差异。
- 对文件访问场景，对照“本人文件”“非本人但同类文件”“无效标识”“格式错误标识”四类响应差异。
- 对路径参数场景，对照“合法业务值”“超出业务范围的路径语义”“规范化前后等价路径”三类响应差异。
- 对比的重点是状态码、响应体关键字、目录索引特征、`Content-Type`、`Content-Disposition`、响应长度和错误提示。

3. 最小化验证
- 目录浏览只验证到能看见目录清单、父目录入口或敏感文件名即可，不递归遍历，不批量抓取。
- 文件遍历优先用文件名、大小、下载响应头、预览摘要或少量内容片段证明“非本人对象可访问”。
- 若已能证明对象级授权缺失，在确认 1 个非授权对象后停止，不继续枚举整段对象编号。
- 若响应暴露物理路径、配置路径或异常堆栈，留存一次证据即可，不反复触发。

4. 影响面判断
- 判断是匿名可利用还是登录后可利用；这会直接影响风险定级与修复优先级。
- 判断影响范围是单一目录、单一接口，还是同一文件服务层下多个入口共享同一缺陷。
- 判断暴露的是目录信息、文件元数据，还是可直接读取业务附件、配置文件、日志、备份、二进制或源码类对象。
- 判断对象标识是否可预测、可稳定复现、可跨角色复现；若可以，通常说明问题不止是展示缺陷，而是访问控制缺陷。

5. 留证与复测
- 将基线请求、修改后请求、最小化响应证据、账号角色关系和时间点一起固化，确保报告可复核。
- 修复后按原入口、同类入口、同层目录和同服务接口复测，避免“只修一个地址、同类点位仍可复现”。

## 关键判断点

- 访问目录返回目录索引页、父目录入口、文件清单或默认目录页，而不是 403、404 或业务化拦截页，可判定为目录暴露信号。
- 同一认证态下，仅修改对象标识或路径参数，即可访问非本人或非本租户文件，可判定为文件访问控制失效信号。
- 若目录中出现配置、备份、日志、组件包、调试文件、业务附件等名称，即使未完整下载内容，也足以说明潜在影响面较大。
- 若目录仅暴露公开静态资源，且访问边界与业务设计一致，应谨慎定性，避免把“公开资源”误报为“目录遍历”。
- 若无效对象与非授权对象返回完全相同的拒绝结果，而合法对象正常访问，说明控制可能有效；不要仅凭可预测 ID 就直接定漏洞。
- 若修复后仅把 200 改成跳转页，但实际仍可通过其他入口、缓存路径或同服务接口访问，不能视为修复完成。
- 文件遍历与普通越权的区别在于对象是“文件或文件映射资源”；目录遍历与信息泄露的区别在于证据核心是“目录可列举或目录边界失守”。

## 证据链要求

- 记录测试前提：测试时间、所用账号角色、是否为低权限或跨角色对照。
- 保留一组完整对照：合法请求、非授权请求、无效请求，以及它们的状态码、响应长度、关键响应头和关键响应片段。
- 对目录浏览，保留能证明“目录可列举”的关键特征，例如父目录入口、文件列表样式、敏感文件类型名称，但避免存储完整敏感文件内容。
- 对文件遍历，保留能证明“对象不属于当前账号仍可访问”的证据，例如对象标识差异、响应文件名差异、归属字段差异或业务上下文差异。
- 记录影响范围判断依据：是否匿名可用、是否跨租户、是否可预测、是否涉及配置/备份/附件等高价值对象。
- 对修复复测，保留修复前后同一请求的差异证据，优先体现“原来可访问、修复后被稳定拒绝”的变化。
- 所有证据保留完整原始字段，包括真实账号、真实文件内容、真实 URL 和真实密钥；仅在文件体积受限时截断 body 并注明。

## 风险定级思路

- 低危或提示：仅暴露有限目录信息，未发现敏感文件名、未发现可直接读取非公开文件，且路径本身接近公开资源区。
- 中危：可列出目录或可访问部分非公开文件元数据，说明服务边界失守，但尚未证明可稳定获取高敏感内容。
- 高危：可直接读取配置、备份、日志、业务附件或跨账号文件内容；或低权限账号可稳定访问非本人对象，且对象标识明显可预测。
- 上调因素：匿名可利用、多系统共享同一文件服务、跨租户影响、文件对象可批量遍历、目录中出现高价值文件类型、修复绕过面明显。
- 下调因素：仅限公开静态目录、无敏感对象、访问结果符合产品公开设计、需要多重前置条件且不具备批量性。
- 定级时不要只看“能不能列目录”，要结合认证门槛、对象敏感度、可预测性、横向影响范围和修复复杂度综合判断。

## 修复与复测

- 对目录浏览类问题，关闭目录索引与自动列目录能力，禁止 Web 根目录直接暴露非公开文件夹，移除调试、备份和临时发布目录。
- 对路径参数类问题，在服务端做路径规范化与基路径约束，只允许访问白名单目录或白名单文件映射，禁止把用户输入直接拼接到文件系统路径。
- 对文件对象类问题，在每个下载、预览、导出入口执行对象级授权校验，校验对象归属、租户归属和角色边界。
- 不要把“将顺序 ID 改成不透明 ID”当成唯一修复手段；若授权校验缺失，标识再复杂也只是增加猜测成本。
- 优先将敏感文件存放在 Web 根目录之外，通过受控下载服务按授权映射输出，并补齐访问日志和异常告警。
- 复测时至少覆盖：原始入口、同类下载入口、同服务层其他文件接口、同级目录、无效标识、非授权标识、规范化路径变体。
- 修复通过的标志应是“合法对象仍可访问，非授权对象稳定拒绝，目录不再可列举”，而不是单点 403 或页面跳转。

## 报告表达模板

- 漏洞概述：在测试过程中，发现 `<入口类型>` 存在路径遍历与文件遍历风险。攻击者在 `<认证上下文>` 下，可通过访问 `<目录入口或对象参数>` 获取原本不应暴露的目录信息或文件对象。
- 成因说明：问题通常由目录索引配置不当、路径约束缺失，或文件下载/预览接口缺少对象级授权校验导致。
- 验证方式：测试使用 `<低权限角色或对照角色>` 构造合法请求、非授权请求与无效请求进行对照。结果显示，仅改变 `<参数类型>` 或访问 `<目录类型>` 后，系统仍返回可识别的目录列表或文件访问结果。
- 影响说明：该问题可能导致目录结构、配置文件、日志、备份文件或其他业务附件暴露；在存在跨账号访问时，还可能造成横向数据泄露。
- 风险判断：结合 `<是否匿名可用>`、`<对象敏感度>`、`<是否跨租户>`、`<对象标识可预测性>` 和 `<影响范围>`，综合评估为 `<风险等级>`。
- 修复建议：关闭目录索引，收敛文件访问入口，实施路径白名单与对象级授权校验，并将敏感文件迁出 Web 直接访问路径。
- 复测结论：修复后，对原始入口及同类入口复测，目录访问应返回拒绝或业务化错误结果，非授权对象访问应被稳定拦截，合法对象访问不受影响。
